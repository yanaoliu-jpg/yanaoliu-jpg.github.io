## 需要装的东西

```bash
brew install imagemagick webp
```

放**影片**才需要这个（只放照片不用装）：

```bash
brew install ffmpeg
```

> ⚠️ 装完 ffmpeg 如果 `build.py` 开始刷屏「AVIF 比 WebP 还大」，
> 跑一次 `brew reinstall libheif` 就好——ffmpeg 带进来的 x265 会让 libheif 加载失败，
> ImageMagick 的 AVIF 就悄悄变得又大又糊。详见 CLAUDE.md 第七节。

生成中文字体子集还需要（只在你电脑上用，访客不需要）：

```bash
pip3 install fonttools brotli
```

Python 用系统自带的就行（要 3.11 以上，因为用到了内置的 `tomllib`）。
没有其他依赖——没有 npm，没有框架，没有 `node_modules`。

## 第一屏、导航、亮暗切换（2026 年 9 月 29 日「放映厅」改版）

- **首页第一屏**是你七组照片的封面轮流全屏：每张停 6 秒，缓慢推近、顺着裁掉的方向平移，再淡入下一张。
  右下角写着「正在放映」哪一组，点了进那一组；旁边有暂停键。
  **某张裁得不好**（重要的东西被裁到屏幕外），在那一组的 toml 里写一行重心，比如
  `hero_focus = "50% 30%"`（横向 50%、纵向 30% 那个点对准屏幕中央），跑 `build.py` 就行。
- **每一页顶上一条导航**：照片 · 影片 · 影评 · 关于。往下读时它会自己收起，往上滑一点就出来，不挡照片。
  手机上收成一个「菜单」按钮。
- **默认暗色，导航右边的太阳 / 月亮按钮可以切到亮色**（亮色的首页就是 9 月 21 日那版渐变）。
  读者切过一次，换页也记得。全屏看照片的灯箱和首页第一屏永远是暗的。
- 3D 光圈镜头撤掉了（`lens.js` 和 Three.js 都删了，git 历史里还在）；换页时的九边形光圈还在。
- **首页的影片是竖版海报卡**：画面、片名、「时长 · 类型」、自述第一句、署名，有奖的那部多一行带月桂叶的奖项。
  鼠标停上去画面会动起来（一段三四秒的无声预览），点了在本页弹出播放器，有声放；按 Esc 或点空白处关掉。
  按住 ⌘ 点还是照常打开影片页。
  **加新影片**时在它的 toml 里多写几行：`genre`（类型，中文段里也写）、`award_short`（有奖才写）、
  `preview_at` / `preview_len` / `preview_crop`（预览从第几秒起、多长、要不要把底部字幕裁掉）——
  例子和挑片段的方法在 CLAUDE.md 第六节「加一部影片」。

## 照片的排法（2026 年 9 月 30 日「放映厅」第三步）

- **首页照片墙每一行都铺满**：七组排成 4 + 3 两行，左右都齐，同一行等高（两行各自一个高度）。
  加新的一组**什么都不用做**——排法每次按张数和宽高比整体重算，加组只会多出一行，已有的封面不会变瘦。
- **系列页照片上方有「逐张 · 网格」两个按钮**。默认逐张（一屏一张）；点「网格」九张一眼看全，
  鼠标停上去显示编号和日期，点任何一张照样进全屏。每次打开都是逐张，不记忆。
- **全屏看照片时说明分两行**：第一行编号和拍摄时间，第二行机身、镜头和参数
  （「Sony α7 IV · Sigma 24-70mm F2.8 DG DN Art · 50mm · f/2.8 · 1/500s · ISO 1250」）。
  机身镜头**只从每张照片自己的 EXIF 读**——导出时抹掉了的那几组就不显示，不会拿页脚的器材去填。
  **换了新相机或新镜头**：构建时会提示「对照表里没有某某」，去 `site/build.py` 的 `GEAR_NAMES` 加一行
  （EXIF 里的原文 → 英文和中文的写法），不加也能用，只是原样显示型号。
- 导航、第一屏、首页各区、页脚、内页标题的**左边缘对在同一条线上**；大屏上内容居中、最宽 1500px。

## 动效（2026 年 9 月「透过镜头」改版，大部分还在）

- **颜色是从你自己的封面里取的**：首页的环境光、区标题的渐变字、内页顶上那片光晕、进度条，
  全是 `build.py` 从每组封面里算出来的。**加新作品什么都不用做**，颜色会自己算好
- 鼠标停在封面上，封面会像拿在手里的照片那样歪一下（最多 5°），还有一个跟着鼠标的小圆圈
- 影评那面海报墙在宽屏上卷成一个能拖着转的圆筒（走马盘）
- 换页时新页面从一个九边形的光圈里张开；全屏看照片时照片从原位放大、关掉缩回去

**三种情况会自动变安静，不用你管：**

| 情况 | 会怎样 |
|---|---|
| 系统里开了「减弱动态效果」（Mac：系统设置 → 辅助功能 → 显示） | 第一屏停在第一张（可以按播放），没有倾斜、跟随光标、换页动画，走马盘不自转 |
| 手机、平板 | 没有倾斜和跟随光标；窄屏上海报墙还是原来的网格 |
| 浏览器太旧、关掉了 JavaScript、或者开了省流量 | 第一屏是第一张静止的照片，只有暗色，其余内容照常 |

## 双语

网站有中英两版，图片只存一份，两边共用：

```
/                      英文（招生官默认看到这个）
├─ /good-night/
├─ /goodbye-renfen/
└─ /zh/                中文
   ├─ /zh/good-night/
   └─ /zh/goodbye-renfen/
```

导航右边的 `EN / 中文` 按钮会跳到**对方语言的同一个页面**，不是跳回首页。

每个 toml 文件底部的 `[zh]` 那一段就是中文版。**没写的项会自动用英文，不会开天窗**——
所以加新作品时可以先只写英文，中文之后补。

### 改完中文一定要重新生成字体

```bash
python3 site/build.py && python3 site/tools/subset_font.py && python3 site/build.py
```

看着啰嗦，但顺序是必须的：先生成网页 → 扫描网页里用到的字 → 裁字体 → 再生成一次把新字体复制过去。

原因：完整的思源宋体有 25MB，不可能整个塞进网页。脚本只打包你实际用到的字（目前 1548 个，约 525 KB；模板里的注释不算，它们不显示）。
第一次跑会把完整字体下到 `素材/字体/`（不进仓库），之后每次都在本地裁，不联网。
**如果加了新字却忘了跑，那几个字会悄悄掉回系统默认字体**，不报错但很难看。
脚本最后会自己检查覆盖率，缺字会直接报错。

### 如果字体脚本报网络错误

比如 `SSL_ERROR_SYSCALL in connection to github.com` —— 那是第一次下完整字体时连 GitHub 的
临时故障（之后都在本地裁，不再联网），**不用慌，也没弄坏任何东西**：脚本下载失败时会先退出，
不会覆盖已有的字体文件。

先确认现有字体够不够用：

```bash
python3 site/tools/check_font.py
```

- `✓ 全部覆盖` → 现有字体够用，直接推送，字体那步不用管
- `✗ 缺 N 个字` → 等网络好了再跑一次 `subset_font.py`；在那之前先别推中文改动

## 改文字

网页上所有文字都在 `site/content/` 里，一个作品一个文件：

| 文件 | 管什么 |
|---|---|
| `_site.toml` | 首页：你的名字、开头那段 intro（第一段也是第一屏那句话）、「关于」里的所在 / 器材 / **邮箱** |
| `good-night.toml` | Good Night / 晚安 |
| `goodbye-renfen.toml` | Goodbye, Renfen / 再见，人分 |
| `the-old-days.toml` | The Old Days / 旧时光 |
| `night-wind.toml` | Drunk on the Night Wind / 夜风沉醉的旅程 |
| `keep-going-back.toml` | I Keep Going Back / 我总是回到那几天 |
| `looking-forward.toml` | Looking Forward / 留给日后 |
| `sea-and-light.toml` | Sea and Light / 海与光的诗 |
| `stop-scrolling.toml` | Stop Scrolling, Stay Alive / 停止滑动，面对生活（影片） |
| `gratitude.toml` | Gratitude, Quietly / 感恩悄然发生（影片） |
| `make-a-wish.toml` | Make a Wish / 都值得被听见（影片） |
| `film-notes.toml` | 62 篇影评，一条一个 `[[entry]]` |
| `_posters.toml` | 海报对照表，**生成的**，别手改（除非要钉死某一部） |

下划线开头的文件不会被当成作品系列。**这不是可选的**——`_posters.toml` 少了下划线，
`build.py` 会拿它当一个作品，然后报错。改完存盘，重新跑 `python3 site/build.py` 就生效。

**没填完的地方写成【这样】，网页上会显示成橙色虚线框**——故意做得刺眼，
就是为了不可能在没写完的情况下不小心发出去。

## 加一期新作品

```bash
cp site/content/good-night.toml site/content/新系列名.toml
```

打开新文件，改这几行：

```toml
slug   = "new-series"        # 网址会是 .../new-series/，定了别再改
title  = "New Series"
source = "第一年/某个文件夹"    # 指向 素材/ 下面的文件夹
order  = 3                   # 目录页上排第几（**按拍摄时间**，不是按加入顺序）
cover  = "DSC01234"          # 目录页封面（文件名，不含扩展名）
```

把 `[alt]` 那一段整个删掉重写（对应新的文件名），然后：

> **两样东西不用写**：标题上方的「Series 06 / 第六组」由 `order` 自动生成；
> 系列页底部的「下一组」也按 `order` 自动首尾相接（最后一组绕回第一组）。
> 加一组进来，编号和链条都自己接上。

```bash
python3 site/build.py
```

照片会自动按拍摄时间排序，横竖构图自动处理。

### 如果照片的 EXIF 被抹掉了

经过微信或手机相册导出的照片，拍摄时间常常会丢。这时候在 toml 里加一行：

```toml
date = "2024-05"     # 只写到月份
```

写了之后，页面上只标月份，逐张不再标日期——我们只知道月份却标出"某月某日"，
那是在编造精确度，而且很容易跟你自述里写的时间对不上。

## 发布到网上

网站产物在 `docs/`。GitHub Pages 可以直接从这个目录发布：

1. 在 GitHub 上新建一个仓库（**Public**，不然招生官打不开）
2. 把本地仓库推上去
3. 仓库页面 → **Settings** → **Pages**
4. Source 选 **Deploy from a branch**，分支选 `main`，目录选 **`/docs`**
5. 等一两分钟，网址是 `https://<你的用户名>.github.io/<仓库名>/`

之后每次更新，重新构建再推一次就行：

```bash
python3 site/build.py && git add -A && git commit -m "更新作品集" && git push
```

## 几个已经替你想过的问题

**为什么默认是暗的？亮色在哪？**
9 月 29 日你要「暗色调、电影感」，所以默认全站暗色。9 月 21 日那次换亮底，是因为灰调封面摆在
一片平的黑底上发浑；这次第一屏是全屏照片、每张封面四周有一圈它自己颜色的光，不再是那片平的黑。
**亮色一行没删**：导航右边的太阳按钮点一下就是（首页是渐变，内页是纸色）。
看全尺寸照片的灯箱永远是暗的：暗部细节在白底上会看没。暗底用 `#0d0e11` 而不是纯黑，
是为了让画面最暗处仍然和页面有边界。

**联系邮箱写在哪？**
`site/content/_site.toml` 的 `email = ""`。空着，「关于」里就没有「联系」那一行、页脚也不写；
填上之后跑 `build.py`。网站是公开的，公开的邮箱会收到垃圾邮件。

**字体是什么？**
EB Garamond（拉丁）+ 思源宋体 Noto Serif SC（中文），2026 年 10 月从 DM Sans + 思源黑体换回衬线——
你要「字体再艺术一点」，参考的是纪实摄影集。英文的作品名用斜体，像书里提到作品名那样。
都自托管，不向 Google 发任何请求。

**首页第一屏的全屏照片会不会把网页拖慢？**
一开始只下第一张（跟封面是同一批文件，不新增），下一张在轮到它之前 2 秒才下；
滚出第一屏、切到别的标签页就停。开了省流量的手机只看到第一张静止的。

**颜色会不会让字看不清？**
不会，这是算出来的，不是凭眼睛调的：颜色的亮度都是构建时钳住的，
验证脚本还会**截图量真实的像素**再查一遍——两种模式各一遍，第一屏七张照片逐张量。

**图片压到什么程度？**
每张出 3 个尺寸（900/1600/2400px）× 3 种格式（AVIF/WebP/JPEG），
浏览器按屏幕和网速自己挑。主力是 AVIF，实测暗部误差优于 JPEG q90，
体积只有它的四成。跟原图 100% 放大对比过，看不出差别。

**为什么每张照片按高度对齐，不按宽度？**
这组有横有竖。按宽度铺满的话竖构图会大得离谱、横构图显得小气。
限制高度让宽度自然生长，横竖片视觉重量才相等——画廊挂画就是这么对齐的。

**照片会不会泄露我家地址？**
不会。原图里本来就没有 GPS 信息，而且构建时会把所有 EXIF 元数据剥掉，
只保留网页显示需要的那几项（时间、光圈、快门、ISO），那几项是写进 HTML 的文字，
不是藏在图片文件里的。

**以后作品多了，仓库会不会太大？**
`docs/` 就是 GitHub Pages 发布的站点，**硬上限 1 GB**，现在 380 MB，还剩约 644 MB。
影片 258 MB、照片 114 MB、62 张影评海报只占 5.9 MB。
一期照片约 16 MB，**影片每分钟约 15 MB**——影片是最大的一块。

**但真正卡住你的不是总量，是 GitHub 的单文件 100 MiB 硬限制。**
现在离硬限最近的是 `make-a-wish.webm`（83.7 MiB，84%），不是 mp4。
详细的账和解决方案在 [容量规划.md](容量规划.md)。

再往后只能精选——招生官不会看 68 期，精选比全堆上去有效得多。

**加影评要 TMDB 的 key 吗？**
只有拉海报那一步要。免费，到 <https://www.themoviedb.org/settings/api> 申请，
然后 `export TMDB_API_KEY='...'`。**别写进仓库里的任何文件**——仓库是 Public 的。
构建本身不联网。
